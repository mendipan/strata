# Strata Studio runner developer preview

Codex **0.162.1** supports this integration through experimental named permission profiles and the explicit Windows **MXC** backend. Its legacy `readOnly` schema is not the restriction interface used here. Schema compatibility is separate from native host qualification; a passing preflight never claims that MXC works on your machine.

Requires Node 22 or newer. Choose Codex or Claude in Studio Settings, extract this package on your chosen Windows machine, then start `Install.ps1`. Pairing uses the exact HTTPS Studio URL and a short-lived, one-use code entered through attended stdin. The runner connects outward; it opens no inbound listener.

Before creating a pairing code, run `node studio-agent-runner.js --check-codex --codex-bin C:\absolute\path\codex.exe`. This offline check probes version and generates `--experimental` schemas in a fresh isolated home. It checks named permissions, runtime workspace roots and active-profile readback in `ThreadStartParams`, `TurnStartParams` and `ThreadStartResponse`, then pins their combined digest. A successful check reports binary/schema digests, source pin and `native_qualified: false`; it never starts a session, signs in or calls a model. A `.cmd`/`.ps1` npm launcher is not the native executable. Preserve any existing CLI and obtain the reviewed CLI executable separately through your approved software process. The source pin remains `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d` (`rust-v0.162.1`); no speculative newer version is required.

Every native thread receives a fresh task-scoped profile through transient configuration overrides: filesystem root denied, only the exact intent snapshot readable, no writes or platform-default read grants, and command networking disabled. The experimental profile selection and exact runtime workspace root replace the old `sandbox`/`sandboxPolicy` fields. The runner checks returned model, approval policy, profile identity, absence of an inherited parent, working directory and workspace root before native turn admission. Shell, web and MCP refusal stays in place; ordinary native user-message items are accepted as input, never included in the agent answer. CLI flags require `windows.sandbox="mxc"` on the dedicated process; no fallback, saved native config, service, sandbox users or ACL rewriting is requested.

Before live use, qualify MXC with the exact binary and profile in a disposable synthetic workspace, without credentials or model calls. The required checks are readable snapshot data, refusal of unrelated file reads and all writes, blocked child networking, and exact process-tree cancellation. Failure to start the probe or enforce any rule leaves the host unqualified; do not add broad root or `:minimal` access to force it to pass. Windows build number and `windowsSandbox/readiness` alone are insufficient. Detailed probe scope and primary source references are in `docs/agents/STUDIO_CODEX_S2_HANDOFF.md` in the source checkout. Native file/process policies apply to tools; app-server itself must still read its own private authentication/history.

The version is checked before consuming a pairing code and its byte digest is pinned afterward and verified on every start. The runner uses a separate `codex-home`, its own stdio app-server and file credential storage in that home. It does not connect to existing desktop chats, use the desktop credential store, or copy existing authentication. Once paired, choose **Sign in to Codex** in Settings and complete the official device-code sign-in. Only the verification URL and one-use user code reach Studio; native account tokens stay on the Windows machine. After sign-in, refresh status and choose a model from the runner's available text models. A model outside that catalog is refused; account access is rechecked before native admission and no fallback model is selected.

Claude installs the separately pinned SDK **0.3.296** from the enclosed lockfile, verifies its declared CLI version **2.1.296**, and asks for its own API key through attended input. The key stays encrypted on that machine. Tools, plugins, MCP and inherited settings are disabled by the bridge. Native filesystem isolation remains a qualification gate; SDK settings alone do not prove it.

New runner directories receive a current-user-only inheritable DACL. Existing directories and ACLs are preserved and checked; broad SYSTEM, administrator or group grants are refused by the conservative verifier. If an existing directory fails verification, reconcile it explicitly rather than weakening the checks. The native verifier does not isolate hostile processes running as the same user or privileged administrators.

Leave the console runner running, refresh its status in Settings, add the paired agent with an exact available model, and approve project context in Agent. Closing it makes it offline. Subsequent starts use `node studio-agent-runner.js --state-dir ABSOLUTE_RUNNER_DIRECTORY`; do not repeat pairing or initialization. A later Claude key replacement uses `--save-api-key --key-stdin` through attended input.

Pairing refuses an existing `runner.json` or `pairing-pending.json` before sending a code. A lost pairing reply leaves the pending marker for operator reconciliation; it cannot be retried by rerunning the installer. Never remove that marker to force another pair. One console runner at a time holds the private `.owner.lock`; after an unclean exit, reconcile the original local/Studio state before an operator removes a stale lease. Normal shutdown releases its own lease. No service, scheduled task or autostart entry is installed.

To accept one proposal, open **Agent**, approve the exact selected intent context, start a conversation, then choose **Prepare draft**. Inspect Before/After and any questions. Only your explicit **Save as draft** creates an ordinary owned draft and separate agent provenance. Open its Review link and verify the draft author and native source turn. Stop requests interruption of the original native thread/turn; inspect the original conversation to confirm its outcome. On a lost result or Save reply, use original-operation inspection rather than sending another prompt or Save. Uncertain admissions without an attributable native turn stay unresolved.

This is an attended developer preview. Bounded native Codex proposal Save, recovery and Stop have been demonstrated; instrumented compiled runtime and packaged identity were checked separately. Each new installation still requires qualification. Native authentication, isolation, protocol provenance, model availability, actual runtime limits and interruption require qualification before live use. A timeout or local abort does not prove provider work or billing stopped. Unknown outcomes retain original IDs; never delete journal files to unblock a task. Codex recovery reads an original retained thread/turn. Claude recovery currently reads completed local receipts; uncertain native sessions remain unresolved and are never restarted automatically.
