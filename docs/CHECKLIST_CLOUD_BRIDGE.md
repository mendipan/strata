# Checklist archive and runtime continuation candidate

Node authors, reviews, measures and publishes the checklist. This finite bridge retains that exact already published v0.3 Release/history in native Cloudflare Artifacts and observes a fresh instance of its exact generated module on a private Worker. It creates no semantic Release, new measured validation, current authority, hosted contributor project or durable checklist state.

The [preparer](../scripts/checklist-cloud-prepare.ts) accepts an explicit producer snapshot and separately pinned lane/summary/registry/manifest bytes. Application-specific mapping and generated modules/configuration belong outside Git. It checks quiescence, links, canonical blobs, complete published history, considered losing proposals, reviews, approvals, authenticated action closure, Release/candidate/realization/checker/oracle bindings and exact output bytes. It reuses [read validation](../src/explorer/validate.ts) and the existing historical engine/profile readers. Integrity does not authenticate a copied producer directory or establish current roles; the operator must obtain the snapshot pins from the attended local rehearsal.

The [app wrapper](../src/checklist-cloud-app-worker.ts) receives `createCollection` through a generated static import. It allows only bounded add/get/list/complete/remove/audit calls and creates a new empty instance per request. Its compiled graph excludes profile, checker, semantic engine and Artifacts code. The UI is outside Release coverage. Independent literal sequences retain ten visible audit events and eleven events for the Unicode observer.

The [Workflow](../src/checklist-cloud-workflow.ts) is exported only as a native `WorkflowEntrypoint` by the external generator. It has no fetch, RPC or scheduled ingress. Its fixed eight steps claim one run, durably reserve the entire allowance, stage the closure/index through the existing registry/Git adapter, cold-read exact commit/path/hash/size locators, and call the fixed app service. All steps have zero retries and check the native step context for invocation count one and attempt one before their callback can dispatch. Completed step results preserve cumulative reservations across hibernation. Ambiguous failed operations are not resumed or restarted; their grant remains consumed. Native platform recovery semantics still need independent review, especially failure between provider mutation and durable step completion. The [step-context contract](https://developers.cloudflare.com/workflows/build/step-context/) and installed native types support this guard; it is not a live recovery qualification.

The [attended runner](../scripts/checklist-cloud-run.ts) consumes the bounded authorization in an exclusive local ledger before dispatch, checks frozen source/bundles, reserves each HTTP exchange, reads complete first-attempt step outputs and preserves readback before cleanup. The [management path](../src/checklist-cloud-management.ts) addresses exact named resources. It does not execute a CLI or SDK; [one explicit native HTTPS request](../scripts/checklist-cloud-http.ts), without a pooled retry agent, performs one exchange per consumed private reservation ticket. Host GET orchestration may make at most three independently reserved attempts for explicit transient failures within the original request/time/byte bounds. Mutation requests and Workflow steps never retry automatically. Redirects, pagination metadata/links, malformed envelopes and uncertain absence refuse. Repository/Workflow lists, including empty lists, cannot establish absence. A well-formed missing-resource error from the exact GET endpoint is required. Credentials come only from the separately approved operator's pure header supplier, whose implementation/custody remains separately reviewed; there is no ambient loader, login repair, account selection or deployment action. A failed run without verified token/handle cleanup retains reconciliation evidence and cannot report successful cleanup. The [bootstrap contract](CHECKLIST_CLOUD_BOOTSTRAP.md) specifies cheap preflight, sanitized diagnostics and the combined gross test-budget boundary.

The source freeze follows both host import graphs as well as both Worker graphs, and pins their original/compiled source. It additionally inventories complete installed Wrangler/cf/esbuild package trees and their resolved runtime/optional/present peer dependencies, including dynamic chunks and native assets. Existing credential-like files are outside this code inventory and refuse preparation rather than being read. The runner reverifies the frozen bytes immediately before an approved execution; future separately approved CLI deployment/preflight must do the same. Management does not load another CLI process after that verification. External producer mapping and operator credential-custody implementation remain separate review artifacts.

The [source preservation transform](../scripts/checklist-cloud-profile-source.ts) captures exact Node collection profile, checker and semantic archive strings before bundling. The pinned installed JavaScript parser checks each actual unique module function declaration or const function initializer, rejects ambiguous bindings/body drift and direct reassignment, and identifies executable archive/digest `toString()` call spans. Comments and string data cannot establish function identity or count as live calls. Only those parsed extraction spans are replaced with original source literals. The existing verification, recognizers and reconstruction still execute, and producer Release/checker/profile pins are unchanged. `profile-source-identity.json` is included in the required hashed output inventory, and the parser's installed package/dependency bytes join the source freeze. Booking profiles are not transformed.

Deployment assigns version IDs. A trusted configuration value pins the authorization body excluding those two provider-assigned IDs; its body still binds the exact preparation/source/target, time/spending boundary and retention choices. The private Workflow event supplies the full grant. The Workflow checks its own actual metadata ID, while the app checks its actual metadata ID through the fixed service binding. The local runner also checks the complete full-grant hash and both operator-approved returned IDs. This split avoids a configuration/version hash cycle without adding semantic authority or trusting an arbitrary serialized SecurityContext.

Fixed proposed ceilings remain 80 published records, 2 MiB canonical original JSON, two stage batches, 64 MiB conservative transfer, 2,000 operation reservations, four maximum repository token issuances (the plan uses three), 40 management provider requests (the schedule uses 33 including 12 cleanup requests), 32 operations/request, three maximum app requests (the plan uses two), 30 minutes plus two prepaid cleanup minutes, and zero cloud model tokens/calls. Each management reservation admits exactly one application HTTP exchange, including errors; it does not bound TCP/TLS retransmission or establish invoice bytes. Actual records/packs/step outputs/bundles must fit before activation; no history is dropped and no ceiling is automatically widened. These are application guards, not a verified invoice cap or measured provider usage.

Build-only preparation creates disabled configurations: no public routes, Workers.dev or Preview URLs, one native Artifacts binding with remote local-dev access disabled, one fixed app service, one Workflow with concurrency one, and an empty authorization pin. No run grant or credential is created. The actual accepted producer history and target are required to freeze the final approval package. Credentials, eligibility, metered-charge acceptance with a numeric spending boundary, readiness reads, exact deployment/versions, one run, and exact cleanup/retention all require separate owner approval.

Qualification uses [deterministic synthetic history and strict Git/Artifacts fixtures](../tests/checklist-cloud-contract.test.ts). It does not substitute for a real producer rehearsal or remote provider interoperability. Installed workerd currently supports through October 8, 2026; the new deployment configurations use October 12. Local workerd execution at October 8 is labeled separately. Matching-date qualification or an explicitly reviewed compatibility-date/dependency decision is required before activation. No dependency upgrade is made by this candidate.

[Focused native tests](../tests/checklist-cloud-native.test.ts) exercise a positive structured event through the full verifier/archive/readback/app path and an owned runtime crash after acknowledged synthetic Git mutation, before durable step output. They require the same persisted instance to reenter at attempt two and refuse before any new Artifacts call, with identical reservations. Fixture ingress and transport instrumentation exist only in the test wrapper. Even a passing local emulator test does not qualify Cloudflare infrastructure recovery or provider response parity.

The native binding, private service and persisted-step constraints were checked against [Artifacts Git protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/), [service bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/), [Workflow rules](https://developers.cloudflare.com/workflows/build/rules-of-workflows/), the installed Wrangler schema and pinned installed types. Those sources establish transport shape; they do not establish a successful new cloud run.
