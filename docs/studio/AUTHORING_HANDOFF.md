# Exact authoring handoff in Studio

Studio uses the existing `content.review` operation for an explicitly supplied private Layer. It adds no private-draft discovery, sharing grant, identity provisioning or hosted-write configuration. Author and reviewer must already have configured sessions for the same project and content model. A reader can inspect the available workflow but cannot submit a review without its existing operation grant.

1. The author saves complete intent through **New change**, **Add a Block through an owned Layer**, or **Owned next revision**. Block creation and whole-Layer mediation use their existing forms. Inspect the actual immutable saved revision in Review.
2. On an owned unpublished Layer choose **Prepare reviewer handoff**. Check the exact owner, baseline, revision and digest. **Copy exact draft handoff** copies full private normalized content; share it deliberately with the intended reviewer. Nothing is sent automatically or stored in browser storage.
3. The reviewer opens the same configured project’s Review page and chooses **Review supplied draft**. Paste the packet and choose **Inspect exact supplied draft**. Studio checks the packet/project/model/reference and canonical SHA-256 digest locally. Read the proposed Block purposes, requirements, contracts, acceptance, changed items and any retained source questions. JSON remains available as an advanced detail.
4. Supply a rationale and explicitly choose **Record accepted review** or **Record rejected review**. The host supplies the reviewer identity and checks current grants, project generation and policy. Copy the returned immutable `authoring-review@…` reference back to the author.
5. The author pastes it into **Exact authoring review reference** and chooses **Publish proposal** on that same saved revision. A rejected review cannot publish it. Publication rechecks owner, exact saved revision/content digest and active reviewer authority. Publication does not select a Layer, measure output, validate evidence, approve scope or approve a Release.

The packet is `strata-authoring-handoff/1` with exactly `project_id`, `model_version`, `draft_ref`, `draft_digest` and `draft`. It contains no session, credentials, authorization claims or approval. The digest is integrity for supplied content, not proof of who sent it, its presence in storage or current head. The backend remains authoritative: it normalizes against the immutable baseline before recording the review. An old supplied revision can be reviewed; that attestation cannot publish a newer revision. The reviewer's ordinary read operations still conceal another owner's private draft and its subject-bound retained records. Private revisions do not change that reviewer's visible snapshot generation. The existing engine's publication operation does not require latest owned head; it binds the requested immutable saved revision. This slice preserves that contract and makes no new latest-head authority claim.

CLI parity is unchanged. The same request is `content review --file FILE` containing `{draft, expected_digest, accepted, rationale}`. Studio sends `content.review` with `{record: {...}}` through its existing authenticated, generation-bound operation route. `layer publish EXACT_REF --authoring-review REVIEW_REF` consumes the same immutable review reference. `strata-authoring-handoff/1` is a browser transfer envelope, not a new engine request schema; extract `draft` and map `draft_digest` to `expected_digest` for CLI use.

Cancel or Escape before submission creates no record and restores trigger focus. Editing the packet clears inspection/readiness. Both decisions and inputs lock during dispatch; repeated clicks do not create another operation. A view/connection change closes the dialog. Stale-generation/policy or role refusal displays the actual error and clears inspected readiness. Refresh and re-inspect before another decision. A lost reply, server failure or unparseable response after dispatch locks resubmission; close the form and check the original operation receipt in this connection’s Review inbox. Never automatically retry or claim failure means no record was saved.

## Qualification and remaining work

`tests/studio-authoring-handoff.test.ts` compares browser canonical hashing with the engine and bounds tampered, cross-project, malformed, oversized and deeply nested input. `tests/studio-authoring-handoff-browser.mjs` uses actual contributor factories, CLI setup and rendered Edge forms with synthetic roles. It edits a complete audit draft through the existing revision form, exports/imports the exact content, records both decisions, tests cancellation/focus, edit invalidation, revocation, stale generation, repeated clicks, reader refusal, exact publication, lost-response reconciliation and restart persistence. It verifies the immutable bootstrap baseline stays identical and no validation/approval/Release operation is manufactured. Browser screenshots and receipts remain in a disposable directory outside Git; no live data, provider or model is used.

This bounded slice does not establish independent human usability, a complete browser-only accepted-Release loop, assigned-agent completion or a hosted authoring deployment. Complete Block input remains the existing advanced revision form; a typed editor for arbitrary contracts/requirements is a separate UI item. Final combined-SHA contributor acceptance and an actually assigned actor task remain separate product gates.
