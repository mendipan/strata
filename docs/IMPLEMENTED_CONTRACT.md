# Experimental local implementation contract

This page retains the default local v0.1 contract. Current opt-in Studio v0.3 lifecycle, browser ownership, namespace and native runner scope is summarized in [Studio status](studio/STATUS.md), [self-hosting](studio/SELF_HOSTING.md) and [roadmap](ROADMAP.md). Their named authority is distinct from the fixture identities below.

Read-only CLI reporting includes `review layer|validation|authoring-review EXACT_REF`, a projection separating assertions, imported outcomes and unverified scope using existing inspector permissions and provenance. `doctor` reuses local configuration guards and an optional bounded loopback health GET; `--offline` skips the probe. Neither changes semantic records nor runs checks/agents. See [CLI_REVIEW_DOCTOR.md](CLI_REVIEW_DOCTOR.md) for states, exact bindings, exit behavior and fixture trust limits.

[BLOCK_CONTRACT.md](BLOCK_CONTRACT.md) defines the shared Block JSON contract. The default v0.1 behavior below is preserved. [Content/assets](CONTENT_ASSETS_SLICE1.md) adds explicit opt-in v0.2 validators, exact authoring reviews, bounded PNG/JPEG background retention, backup2 closure and migration preview. [Mediation](MEDIATION_SLICE2.md) enables strict versioned selection/approval/Release for explicitly activated local fixtures, with bounded grant/report checks and inactive archive closure.

This is a bounded implementation of the proposed semantics, not a replacement for `STRATA_MODEL.md` or a production architecture commitment.

## Records and composition

The five semantic objects remain Block, Layer, Composition, Resolution, and Release. JSON schemas under `schemas/` describe the initial records. Unknown normative fields, duplicate declared-set members, unsupported facet values, and unsupported operations fail closed. Object keys and declared sets normalize deterministically; ordinary parameter-array order remains meaningful. Requirements, criteria, relationships, and keyed contract entries are atomic items. Missing and present-null preconditions differ. `set_item` and new Layer acceptance are the only mutations; Block creation/deletion, collection removal, reparenting, cross-version composition, and automatic rebasing are deferred.

Requirement `facets` is a nonempty set of `behavior`, `design`, `data`, and `safety`. Block inspection derives separate own and subtree facet unions. Facets never change authority, create a storage service, override an invariant, or prove coverage. Complete requirement edits conflict as one item even if different actors change different facets. A protected item's facet amendment still requires its fixed guardian.

Each Layer has one server-resolved local fixture owner; public fixture handles do not authenticate hostile callers. Drafts are private to that owner, revisions require the current exact head, and publication freezes the exact revision without selecting it. Required peer reads refer to published exact revisions and require those revisions in the selected dependency graph. Layer dependencies are acyclic; relationship cycles are permitted. Preconditions use the common immutable baseline; assumptions use the final effective snapshot. Layer acceptance enters collision analysis before effective-tree validation.

Composition pins its baseline, full considered set, whole-Layer selection, alternative cardinalities, declared scenario checks, and sealed decisions. Identical writes coalesce while retaining every contributor; differing writes report conflicts. There is no application-order winner. Exact compatibility capabilities come from finite compiled profiles: booking and the small counter architecture fixture. Core inspects no booking fields. Empty/unknown checks block readiness; this implementation does not infer arbitrary prose compatibility. Omitted considered proposals require an explicit sealed select/reject decision. [Profile separation](PROFILE_SEPARATION.md) records the 2026-10-08 boundary, compatibility and regression proof.

A decision comes from a published decision-only Layer. Its unsigned digest binds the Layer, proposal index, baseline/model/scenario/groups, and complete considered set; selection and Resolution refs do not make it circular. Baseline selectors endorse that exact payload before sealing. Select/reject must partition the considered set; free-value repairs, replacement synthesis, coexistence waivers, and defer are outside this slice. Scope uses the smallest declared baseline authority covering changed Blocks, relationship consumers, and criterion subjects. Proposed hierarchy and owner fields cannot grant authority.

## Realization, evidence, and publication

The pinned `booking-node/1` profile recognizes the four fixture Blocks, exact bounded statements and structured parameters, their contract/relationship entries, and explicit mechanical/review criteria. It implements integer hold duration, exclusivity, reminder timing, and the command interface. It rejects additional claims and unsupported design obligations, even when semantic composition is eligible. Each realization manifest enumerates every active requirement, contract entry, relationship, purpose review, standalone criterion, and Layer-added criterion; it binds capabilities, facet handling, check versions/fixtures, output hashes, and reverse links. Coverage begins as `implemented_validation_pending`.

The owned fixture runner executes the generated application. Validation imports results without executing supplied commands, installing code, or trusting an arbitrary executor label. Every active criterion needs exactly one passing result bound to the candidate fingerprint, profile/template fingerprint, and output-tree digest. Review criteria require an explicit `fixture-reviewer` attestation. Imported fixture results are an explicit local trust boundary, not cryptographic proof that an arbitrary caller ran the tests. Passing checks leave responsible-scope and release approvals pending. Guardians are required for protected-item amendments; unchanged invariants cannot be waived by a decision.

Candidate approvals bind the exact candidate and evidence digest, with fixed baseline scope, guardian, and release roles. Release rechecks all these gates, stages complete immutable artifact records, then commits one publication index. Cloudflare uses a SQLite transaction in `ProjectAgent`; the Node harness uses serialized operations and an atomic index-file rename. Neither is described as a distributed transaction. Staged orphan artifacts may remain after a pre-publication failure. Lost responses and concurrent identical requests return the same committed Release. No baseline switches implicitly. Releases contain complete effective snapshots, inherited acceptance and provenance, authority/deleted-ID records, lineage, decisions, validation, and approvals; a fresh composition can use a Release without Layer replay.

## CLI and identity

Commands implemented: `init`, `status`, `inspect`, `diff`, `layer create/revise/publish/restore`, `context show/use`, `compose`, `conflicts`, `resolve`, `materialize`, `distill`, `validate`, `approve`, `release`, and `config show`. Aliases emit canonical command names. All support `--help`; `--version` reports protocol, model, and capability subsets. Default and `--json` invocation emit one JSON envelope and a stable exit code. `--human` adds readable help, status, Block/acceptance inspection, candidate diagnostics and next actions. Input `--file -` accepts one JSON object from stdin. Interactive prompts remain deferred.

All commands require the configured project/broker except help/version. `init` initializes intent within that configured project; it does not scaffold another project or activate a cloud account. Record listings use stable bounded pages and cursors; Block inspection currently requires an ID and `--at` exact snapshot. `diff` compares Release/Composition snapshots; Layer-to-Layer diffs and automatic migrations are deferred. Block selection and authority remain semantic records, not a mutable current-baseline config setting.

Personal `context show/use` stores exact navigation targets and a monotonic generation in broker metadata, scoped by workspace and server principal. `context use TARGET --expect-generation N` rejects stale updates; it never changes semantic records or supplies implicit mutation inputs. Read-back verifies the immutable target fingerprint and derives its baseline/selections. Ordinary Layer publication preserves context. `layer restore CURRENT --from PRIOR` creates the next private revision of the same owned Layer on the same baseline/model, retaining all old records and publication flags. It checks source visibility, complete proposal shape, current head and current Layer/Block scope. Cached restore retries recheck source permissions; exact retries return the same revision after a lost response. New drafts inherit no evidence, approvals or accepted review. Atomic audit metadata binds old head, source fingerprint and result. Abandonment, deployment rollback and mirroring remain deferred. The separate Node backup/inactive-restore slice is implemented; see [LOCAL_BACKUP.md](LOCAL_BACKUP.md). [Milestone usage and tests](LOCAL_RECOVERY.md).

The broker accepts only known local fixture session handles from `STRATA_SESSION`, never `--actor` or a body owner as authentication. These nonsecret handles simulate trusted principals; any local process that knows them can use the fixture principal. Isolation claims concern the mediated API and Agent instances, not hostile local processes or filesystem access. General Agent HTTP/WebSocket routes, callable endpoints, browser-origin requests, and client state synchronization are not exposed.

Fixture handles: `fixture-bootstrap`, `fixture-a`, `fixture-b`, `fixture-c`, `fixture-selector`, `fixture-release`, `fixture-guardian`, `fixture-reader`, `fixture-preparer`, `fixture-reviewer`, `fixture-runner`, and `fixture-backup`. These map to bootstrap, three authors, scope selector, release manager, safety guardian, reader, candidate preparer, interaction reviewer, and evidence producer, and separate backup operator. Authors mutate only owned Layers; readers cannot mutate semantic records, but may change their own personal navigation context. Preparers compose/resolve/materialize/register, interaction reviewers file reports, and only the fixture runner imports its configured executor/review labels. Selector, guardian and release operation grants still require exact baseline semantic authority. Bootstrap may initialize and author owned Layers; it cannot approve or publish Releases. Cloudflare OAuth/GitHub login supplies no Strata identity or budget authority.

Both public brokers share the code-only `FixtureIssuer`. It resolves a normalized context and rejects another project before data access, unknown/expired/suspended fixtures, forbidden operation roles, and configured Layer/Block assignment violations. Default local author fixtures permit any new owned Layer; bounded assignment tests use trusted constructor configuration, with no public grant API. Context freshness and current permissions are rechecked before cached mutation responses and publication. Pending release/sealing also checks the active fixture principals behind required endorsements, without rewriting historical Releases. Cache keys include tenant, project and principal. Hosted construction fails closed: no JWT/OIDC verifier, production membership/delegation, durable revocation or authenticated evidence attestation is implemented.

Requests are bounded to 1 MiB, 32 nesting levels and 20,000 nodes, with strict envelope fields and a 64-operation local ingress/queue guard. These limits are not complete hosted denial-of-service controls; stream deadlines, distributed admission and production rate limits remain pending. Allow/deny audits contain operation/policy/principal/project/ref metadata, never raw prose, evidence or credentials. Commits record a correlated audit atomically with the publication index; audit failure closes writes. Node audit bounds are 16 MiB plus 20,000 commit events, SDK audit bounds 20,000 rows. These local records are not independent or administrator-resistant audit proof.

`--offline` is the default and allows the configured loopback broker. The standard CLI configuration permits only local-persistent-fake; its explicit storage-expectation header makes a differently configured Node broker refuse before store access. Non-loopback brokers and remote CLI adapter configuration fail before access. Redirects are refused. There are no AI bindings, remote fallback calls, telemetry, provisioning hooks, update checks, deployment scripts, or paid-plan activation in the Strata core/CLI. The optional local Wrangler process is gated by native tooling; no remote bindings are configured.

Dry runs execute against a temporary in-memory copy and do not publish semantic records, stage application artifacts, create outputs, or call models. Ordinary semantic readiness previews from missing evidence/endorsements report `execution_ready: false`; that is not Release readiness. Backup integrity/format/reference failures retain `ok: false`, their nonzero exit and structured errors even in dry-run mode. Successful backup verification has `data.verified: true`; a successful restore dry-run has `data.restored: false` and writes no output. Tests verify exact Node index/artifact bytes remain unchanged. The Cloudflare SDK may initialize its own internal housekeeping database when an Agent first starts; that untested runtime behavior is not claimed to be a filesystem-pure dry run. Dry Layer commands avoid creating a new `LayerAgent` instance.

Broker mutation idempotency keys bind principal, operation, and input; changed requests conflict. Reads never reuse a mutation's key. Publish and Release content are naturally idempotent. Materialization refuses existing nonempty output directories, including repeated filesystem export requests; retry with a new empty directory after inspecting a registered realization. That filesystem-export limitation is narrower than the CLI plan's eventual full command-level retry contract.

`materialize` writes only under the selected project, requires a new/empty output directory, and starts no server or browser. Keep realizations under `.strata/` so Release can locate and rehash their actual files; unmanifested files invalidate validation. Runtime application state lives outside the output tree. Traversal and symbolic-link/junction paths are refused. A disk failure after artifact registration may leave a registered realization without local files; it cannot pass local Release preflight.

`distill` currently means `supplied_proposal`: an explicit manifest names the only source files to read and pins their digests. Every proposed item has observed/inferred/correction/uncovered traceability and rationale. It creates an owned draft and requires exact source/draft-bound review with no unresolved questions before publication. Against a Composition, it uses that target's baseline; required peer dependencies and assumptions remain explicit in the prepared proposal. It performs no inference and does not execute source instructions.

[Native Git adoption](NATIVE_GIT_ADOPTION.md) adds explicitly configured local Node operations: `source capture/bind`, `git plan/stage/check/evidence/review/apply/finalize`, and `git transaction inspect/recover`. Source associations pin an exact accepted Release and reviewed selected mapping; supplied patches stage against raw committed bytes in a private repository. Complete application acceptance and separate exact code approval precede explicit journaled working-file changes. Original HEAD/index remain unchanged; owner commits and exact-tree finalization precede explicit successor association. Failed/incomplete application observations remain ineligible for apply. These v0.1 operations preserve the existing semantic validation and Release gates, run no arbitrary command or automatic inference, and gain no default grants. Automatic checking recognizes only the compiled counter fixture. The SDK has no application filesystem backend; historical records remain portable and inactive on backup restore.

Exit codes: 0 success; 1 internal failure; 2 invalid arguments/records; 3 missing reference/project; 4 identity/owner/authority; 5 conflicts/dependencies/stale revision; 6 incomplete or stale evidence/endorsement, or failed backup integrity; 7 forbidden remote/cost boundary; 8 unsupported capability/profile; 9 store/broker/executor unavailable. The prototype reports the first failed prerequisite; aggregate diagnostic precedence and cancellation code 130 are deferred. A valid blocked `compose` persists an inspectable record and exits 5; `inspect` can describe blocked records successfully. Attributed interaction reports block that exact candidate revision without rewriting the Composition.

## Storage and runtime status

The Node-only local backup slice implements `backup create/verify/inspect/restore`; [LOCAL_BACKUP.md](LOCAL_BACKUP.md) specifies commands, format, exclusions, limits and restore-drill evidence. Full indexed exports require the separate `fixture-backup` local operator role and a descriptor-bound quiesced Node state. Cooperative leases exclude the updated broker while exporting and remain held until shutdown drains pending publication/audit work. Verification checks hash/reference/evidence/profile closure and historical ownership metadata. Restore requires the expected project and a trusted manifest digest, writes only to a new/empty isolated inactive archive, and installs no current identities, grants, personal context or request cache. Node startup refuses that archive. SDK/online backup and trust reactivation are deferred; the fixture selector and local hashes do not establish production authentication or cryptographic authorship.


`ArtifactStore` separates immutable artifacts from the registry. The local fake stores content-addressed records in hash-prefix shards. Layer preparation reads only its pinned context, validates through the same Engine, hashes and durably stages new bytes outside the project lock. A short synchronous registry transaction rechecks the owner/head and pinned entries, merges the prepared delta into the current registry, and saves idempotency results. Other project operations remain serialized; the JSON registry still has an O(N) update cost. Legacy single-store local records remain readable.

`CloudflareArtifactsAdapter` now implements deterministic batched Git object trees, immutable branch creation, complete commit-qualified read-back and SHA-256 verification, disposable binding capabilities and bounded credential cleanup. Its narrow binding contract compiles against installed provider types; strict mock tests parse and verify the actual Git pack. Remote construction requires exact account/namespace/project/repository pins, an unexpired trusted host run approval, an injected transport and a shared application budget. The Node broker now accepts a trusted in-process ArtifactRegistryStore with durable exact-commit JSON/binary locators, fresh provider reads and no fallback. Remote-indexed states refuse local-file import and backup. No provider binding, credential bridge, default remote switch or live adapter interoperability is configured; Worker publication remains local. See the [storage integration contract](ARTIFACTS_REGISTRY_INTEGRATION.md) for injected host controls and deterministic checks. A host-configured provider read, including a dry run, needs an explicit unexpired run grant.

The Cloudflare source imports the pinned Agents SDK. `npm run test:agents` exercises local workerd/SQLite ownership, stale-reference guards, failure recovery and the executable Release workflow. The stress harness measures scripted storage operations; it does not establish LLM concurrency or production throughput. Wrangler stays local with no remote bindings.


## Deterministic regression hardening

[The hardening contract](DRIFT_REGRESSION_HARDENING.md) covers mismatched obligation/check edges, timing expectations derived from generated configuration, and missing checker-content binding. Materialization and flattening conserve complete obligations; the host runner requires independently supplied semantic expectations. Explicit Node profiles 3/4 and evidence format 2 pin checker, fixture and oracle bytes. Profiles 1/2 retain their legacy evidence format; old immutable receipts are not silently migrated.

The regression suite executes generated applications with independent item/value/link/provenance checks, fresh measured build mutants, exact dependency pins, stale-evidence refusal and permitted intent evolution. These checks support only the named finite fixture claims. Checker-bound profiles require Node; SDK use returns `UNSUPPORTED_CHECKER_BACKEND`.

## Versioned mediation

[The mediation contract](MEDIATION_SLICE2.md) implements strict approval/2, versioned Resolution/Release and inactive backup2 closure. One finite example policy, a constructor-assigned test executor, exact basis/packet/response, durable one-use receipts, conservative report carry-forward and exact review dispositions are supported. Human selection and post-validation scope/guardian/Release approvals remain separate.

Node tests cover executor durability, failures, restarts, retained assets and deliberate intent evolution with fresh evidence. SDK tests cover asset-free human mediation and measured legacy profile 2. Fixed guardian scopes are explicit; fixture configuration changes require next-generation activation. Historical descriptors and inactive restores grant nothing.

SDK checker-bound/binary parity, hosted identity, active migration, general policies and semantic discovery remain deferred. Use [the verification commands](VERIFICATION.md) for fresh results.
