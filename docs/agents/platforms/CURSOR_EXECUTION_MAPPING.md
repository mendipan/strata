## 2. Operation mapping

All rows describe a future adapter; operator configuration owns the endpoint URL and repository/environment/model/tool settings, and tasks never choose native options. Labels separate **documented shape** (pinned pointer), **proposed normalization** and **gaps**.

**`describe()`** — Pure compiled declaration; zero network or credential access; advertise nothing qualified until the section 7 gates pass.

**`submit(task)`** — Documented: `POST /v1/agents` "Create a Cloud Agent and immediately enqueue its initial run" (`/paths/~1v1~1agents/post/description`); `CreateAgentResponse` requires both `agent` and `run`. **Resource creation is run creation** — checked, not assumed; no non-executing create exists. Proposed: durably reserve `(connection_id, task_id)`, the full request digest and a pre-generated client `agentId` (`bc-<uuid>`, `/components/schemas/CreateAgentRequest/properties/agentId`) **before** the single create; bind the returned `agent.id` + `run.id` atomically when observed. The request carries `prompt.text` = instruction, `repos[0].url` + `startingRef` = the exact approved commit SHA, `workOnCurrentBranch: false`; nothing task-selected. Follow-up `POST /v1/agents/{id}/runs` is never used for the same task — it extends conversation/workspace, and "Only one run can be active per agent at a time" (`/paths/~1v1~1agents~1{id}~1runs/post/description`); a second start stays journal-blocked.

**`status(ref)`** — Documented: `GET /v1/agents/{id}/runs/{runId}` returns `Run.status` ∈ `CREATING, RUNNING, FINISHED, ERROR, CANCELLED, EXPIRED` (`/components/schemas/Run/properties/status/enum`). Proposed: one bounded read-only observation by the exact retained agent+run IDs; never list-scanning by name, date or branch. Normalize `CREATING`→`queued`, `RUNNING`→`running`, `FINISHED`→`succeeded`, `ERROR`→`failed`/`TASK_FAILED`, `CANCELLED`→`cancelled`, `EXPIRED`→`failed` with candidate `TASK_LIMIT`. Gap: `EXPIRED` is undefined in the reviewed inputs, and the endpoints page describes an agent `IDLE` status absent from the pinned `AgentSummary` enum — prose/schema drift to reconcile before implementation. Sequences and digests are adapter-owned; native timestamps are not sequence numbers.

**`result(ref)`** — Documented: `Run.result` is the "Final assistant reply text. Populated once the run terminates" (`/components/schemas/Run/properties/result`). Proposed: normalize the observed terminal run's result text — attributed via the exact retained IDs — into a bounded summary; freeze the canonical digest before `succeeded`; re-serve frozen immutable bytes; `EXECUTION_RESULT_UNAVAILABLE` otherwise. Gaps: artifacts (`/components/schemas/Artifact`: `path`, `sizeBytes`, `updatedAt`; per-agent, at most 100) carry **no digest and no per-run attribution** ("Artifacts are agent-scoped because the workspace persists across runs") and cannot fill digest-bound descriptors; download (15-minute presigned URL, outside the subset) stays deferred. `Run.git` (`repoUrl` scheme-less, `branch`, `prUrl`) is "per-agent state, not per-run" (`/components/schemas/RunGit`): proposed output only — never engine evidence, adoption, merge or download permission; attribution requires `latestRunId` or the unselected stream.

**`cancel(ref)`** — Documented: `POST /v1/agents/{id}/runs/{runId}/cancel` — "Cancellation is terminal — the run transitions to `CANCELLED`"; an already-terminal or never-active run returns `409 run_not_cancellable`; the receipt is `IdResponse {id}`. Proposed: `cancel: "cooperative"`; one cancel POST on the exact retained run; a 200 receipt emits `cancel_requested` (not stop/cleanup proof) then one bounded GET to observe the terminal state; a 409 triggers a bounded GET because completion may have won. Archive/delete are never used as cancellation or cleanup.

## 3. Authentication and authority

Documented: Basic (API key as username, empty password) or Bearer, identical behavior (`/components/securitySchemes/basicAuth`, `/components/securitySchemes/bearerAuth`); a user or service-account API key. Gap: this authenticates the **Cursor account**, never the approved service/instance/source/repository binding; the host `ExecutionGrant` carries those bindings and provider JSON never supplies subject authority ([contract section 3](../EXECUTION_CONTRACT.md#3-connection-lifecycle-and-authority)). Credentials resolve only after admission inside the trusted host and never enter DTOs. After revoke or expiry no cleanup/archive/delete runs under the revoked grant and late output is discarded. Outputs keep `trust: "agent-output"`; digests bind content only; no engine principal, measured-execution authority, publication, independent review or Release permission. Account grants and plan entitlements (`plan_required`, `service_account_required`) are unverified.

## 4. Identity, recovery and repository binding

| Binding | Decision |
| --- | --- |
| Original key/digest | Journal-first ([contract section 4](../EXECUTION_CONTRACT.md#4-task-identity-and-durable-admission)): reserve key and digest before any native call; same key plus same digest is one task; a changed digest is `EXECUTION_CONFLICT` even after terminal. Native exactly-once is **not** established: the only documented dedup is client `agentId` ("Re-POSTing the same `agentId` returns `409 agent_id_conflict` instead of creating a duplicate"; not combinable with `envVars`) — duplicate prevention, not an idempotent reply; `CreateRunRequest` has no idempotency field and run IDs are server-minted. Never claim exactly-once from a Map. |
| Native handles | Bind `agent.id`/`run.id` atomically when observed. A client-supplied `agentId` (retained before dispatch) is preferred; with server-minted IDs recovery stays unsupported. Lost create reply with a retained `agentId`: a read-only `GET /v1/agents/{agentId}` -> `AgentSummary.latestRunId` -> exact-run `GET` is a **conditional candidate**, only for a dedicated, exclusively controlled agent with no foreign follow-up runs and independently established attribution to the original initial run. The client ID, `agent_id_conflict` and `latestRunId` alone do not prove that attribution. Without it, keep the admission uncertain and block every second start; never a second POST. `agent_not_found`/`run_not_found` are observation errors, never proof execution did not occur or resubmission permission. Without a provably retained identity no guessed lookup or list matching by name/date/`prUrl` is permitted. No automatic retry, UUID replacement, provider fallback or post-revoke cleanup. |
| Repository | `RepoConfig.startingRef` accepts "Branch name or commit SHA" (`/components/schemas/RepoConfig/properties/startingRef`); only the exact 40/64-hex SHA is accepted — a mutable branch/ref is refused pre-dispatch. `workOnCurrentBranch: false` keeps proposed commits on a new `cursor/...` branch; `true` is refused. `prUrl` creates are not selected; the host still proves repository membership, and a native branch/PR reference is never code or engine evidence. |
| Project / model / environment | Trusted-host/journal bindings, never native request authority. `ModelRef.id` (`GET /v1/models`, outside the subset) is operator LLM configuration, not `binding.model_version`. `AgentEnv` (`cloud` = Cursor-hosted VMs; `pool`/`machine` = self-hosted workers, `/components/schemas/AgentEnv/properties/type/enum`) is operator configuration reusing already-approved environments; no provisioning experiment. |

## 5. Limits, cancellation and isolation

- Control call at most 10 s: bounds caller waiting only; after invocation, timeout/abort is dispatch `unknown` and native work may continue.
- Requested runtime at most one hour: **no documented run wall-clock deadline**; `EXPIRED` is undefined in the reviewed inputs. A bridge timer plus cooperative cancel is a proposed expiry response, not enforcement; unsupported bounds block qualification.
- Output: `Run.result` has no schema maximum — cap raw bytes before parsing; normalized results stay within the original budget (at most 64 KiB) with at most 16 digest-bound descriptors; the native artifact list (at most 100) is not digest-bound and is not mapped.
- Documented request bounds: at most 20 repos, 5 images (15 MB each), 50 MCP servers, 50 `envVars` (4096-byte values), name at most 100 characters; Strata adds 32 KiB task/status and 16,384-unit instruction caps.
- Concurrency/rate/cost: one active run per agent (`409 agent_busy`); "Standard rate limiting" is documented without figures; `rate_limit_exceeded`/`usage_limit_exceeded` exist; usage/cost endpoints are outside the subset and no cost guarantee is implied.
- Retention: the [security/networking page](https://cursor.com/docs/cloud-agent/security-network#data-retention), rechecked 2026-10-12, documents conversation history kept indefinitely by default, optional Enterprise 90-day conversation retention, and encrypted environment snapshots deleted after 90 days of inactivity (reset by start/resume). This is not a guaranteed immutable `GET Run.result` replay window or proof of original-run recovery; deletion, policy and API retention behavior still need qualification. `stream_expired` concerns SSE only; output expiry must surface explicitly, and partial history or a last message cannot establish success.
- Cancellation: terminal by documentation, but a receipt is not stop/cleanup proof, the completion race is real (the 409 path), `cancel_requested` is not `cancelled`, and a local timer only bounds waiting.
- Isolation: the security page documents "isolated VMs" in AWS, default internet egress with allowlist modes, encrypted secrets/snapshots (about-90-day inactivity deletion), terminal-visible runtime secrets and acknowledged prompt-injection exposure — vendor cloud-workspace statements, **not proven Strata isolation**. Per-task dedicated agents reduce state coupling but qualify nothing; Privacy Mode (legacy) is unsupported for Cloud Agents.

## 6. Errors

The shared rule applies at adapter-method invocation ([contract section 6](../EXECUTION_CONTRACT.md#6-errors-and-recovery)): every failure after invocation is dispatch `unknown`, including authentication, validation and journal conflicts; only a pre-invocation guard refusal may be `not_dispatched`. Native codes map to finite sanitized common codes, and native `message`/`helpUrl`/`provider` text never enters persisted records: `unauthorized`/`api_key_not_found` → `EXECUTION_AUTH`; `agent_not_found`/`run_not_found` on retained-ID reads → `EXECUTION_NOT_FOUND`; same-key changed request or irreconcilable `agent_id_conflict` → `EXECUTION_CONFLICT`; `rate_limit_exceeded`/`usage_limit_exceeded` → `EXECUTION_LIMIT`; `validation_error`/`invalid_model`/`invalid_branch_name`/`repository_required`/`repository_access` → `EXECUTION_INVALID`/`EXECUTION_BINDING`; 5xx `internal_error`/`upstream_error`/`not_implemented` → `EXECUTION_UNAVAILABLE`; transport loss/timeout/abort after create → `EXECUTION_UNAVAILABLE`/`EXECUTION_TIMEOUT`/`EXECUTION_ABORTED` with a retained uncertain admission. An observed `ERROR` run is `failed`/`TASK_FAILED`; an observation failure is never invented into a terminal task state.
