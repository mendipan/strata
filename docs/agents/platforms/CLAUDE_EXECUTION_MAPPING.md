Status: source-pinned mapping proposal with synthetic normalized DTO fixtures; native execution remains unqualified. **No functioning or qualified Claude execution integration is delivered.** There is no adapter implementation, durable journal, runtime test, binary launch or host wiring. Passing the fixtures establishes shared DTO consistency only. The Claude row in [COMPATIBILITY.md](../COMPATIBILITY.md) stays a candidate; accepting this document does not advance execution qualification. Cloudflare remains first. KIT, CF and Settings retain their existing ownership.

The normative authority is [execution/1](../EXECUTION_CONTRACT.md), especially its [independent assignments](../EXECUTION_CONTRACT.md#8-independent-next-assignments) and the pre-selected Claude direction: an operator-owned Agent SDK/binary bridge with both sides pinned, isolated workspace/tools and separately mapped lifecycle, results and cancellation ([contract section 7](../EXECUTION_CONTRACT.md#7-cloudflare-first-and-platform-seams)). The published [Codex proposal](CODEX_EXECUTION_MAPPING.md) illustrates structure and qualification care only; no Codex native guarantee, schema pin or field name transfers to Claude. This review started from the minimal public snapshot of base `c722c7a5d5feaedb8488008a1c3f10d5514d1251`. No runtime launch, account access, credentials, provider calls, UI automation, publication or deployment are authorized by this mapping.

## 2. Operation mapping

All rows describe a future adapter. SDK import, executable resolution and bridge startup belong to explicit supervised startup, never `describe()` or disconnected Settings display.

| Operation | Proposed native calls and requirements |
| --- | --- |
| `describe()` | Pure compiled declaration; zero spawn, credential or provider calls. Do not advertise qualified capabilities until the gates below pass. |
| `submit(task)` | Durably admit the complete strict task and authorization in the host journal, then reserve `(connection_id, task_id)` and request digest in the separate adapter journal before native start. Exactly one `query({ prompt: input, options })` per task lifetime, where `input` is an `AsyncIterable<SDKUserMessage>` yielding one `{ type: "user", message: { role: "user", content: task.instruction }, parent_tool_use_id: null, uuid: hostInputUuid }`. A string prompt selects single-message mode and cannot be called streaming input. No later inputs, steering, resume or second query are selected. Keep the input channel available for interruption until the attributable completion, then retire it under qualified lifecycle policy; an actual generator lifecycle is not implemented by the fixture. Operator-owned options bind `cwd` to the approved isolated checkout, sandbox/settings/tool policy, reviewed `permissionMode` (never `bypassPermissions`), fail-closed `canUseTool`, `persistSession: true`, `sessionStore`, host-derived `sessionId`, bounded `maxTurns`/`maxBudgetUsd`, and a grant-bounded `abortController`. Bind observed init identity before reporting a bound snapshot. A callback alone does not enforce the entire tool policy. |
| `status(ref)` | Resolve the original ref in the adapter journal and perform one bounded observation of its retained state. `getSessionInfo` is display metadata and `getSessionMessages` returns user/assistant/system conversation history, not a terminal `SDKResultMessage`. History may be compacted; mirror writes are best-effort. Neither proves running or terminal success. Reconciliation needs a separately retained, uniquely attributable completion from the original query stream, bound to the original request and observed session. Without it, report an observation error and retain uncertainty. Bound helper reads to the approved directory/store and raw byte/time budgets. `resume`, `continue` and `forkSession` create or extend work and are excluded from status and loss recovery. |
| `result(ref)` | Serve the immutable normalization frozen from an attributable original-stream `SDKResultSuccess` (`result: string`), with the original request/session binding. Normalize bounded final text and retained changes into a summary and opaque artifact descriptors; freeze result/digest before `succeeded`. Re-serve frozen bytes under current result authorization, without transcript-based recomputation, restart or extension. Artifact retrieval is deferred. A success result projection is not proof that the selected runtime stopped all task work; qualify terminal semantics and background work before using it. |
| `cancel(ref)` | Return a retained terminal snapshot if available. Otherwise one `query.interrupt()` against the live streaming-input query. Its return is `SDKControlInterruptResponse \| undefined`, not an SDKMessage event. A receipt requires the observed `interrupt_receipt_v1` capability; version pairing alone cannot prove it. The selected method returns `still_queued` and never sends `cancel_queued`, so its receipt does not carry `cancelled`. Empty lists do not prove stopping; queued inputs/subagents and completion races remain gates. Emit `cancel_requested` after an accepted interrupt, and use attributable runtime outcome for any terminal state. A local call AbortSignal only bounds waiting. The documented SDK abort path closes subprocess stdin and later signals abort; it can affect process lifetime, but attributable native stopping and side effects remain unverified. Repeated cancellation must be idempotent in the adapter journal; repeated native interrupts remain unqualified. No direct control-protocol cancellation or kill fallback is selected. |

Reviewed literals: streaming input is the iterable branch of `query`; `interrupt()` is a control method with an optional receipt. Synthetic native entries omit fields and are not native schema-conformance evidence.

## 3. Authentication and authority

The host retains a separate execution approval and supplies current authenticated `ExecutionGrant` metadata before and after operations ([contract section 3](../EXECUTION_CONTRACT.md#3-connection-lifecycle-and-authority)). Bridge process custody must independently authenticate the approved runtime/instance and bind every native session/result to the grant.

Downstream authentication documented by the [quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart) is `ANTHROPIC_API_KEY` (not auto-loaded from `.env`), with third-party model providers selected by `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_ANTHROPIC_AWS`, `CLAUDE_CODE_USE_VERTEX` or `CLAUDE_CODE_USE_FOUNDRY`. These authenticate model access only: a model API alone is ineligible, and no consumer Claude login is assumed to be an authorized third-party integration. The SDK spawns a local child process, which supplies no independently verified remote service subject; `expected_subject` semantics for a local binary bridge remain an unverified host design gate. Discovery approval, SDK installation and provider JSON never grant execution or engine authority. Operator-managed downstream credentials are resolved only after authorized admission inside the trusted host; this review reads no credentials and specifies no store changes. Revoke/expiry/invalidation discard late output and deny further access; no cleanup interrupt is issued under a revoked grant. Disconnected display performs zero runtime/account calls.

Outputs retain `trust: "agent-output"`. Digests bind content only. `total_cost_usd` is documented as a client-side estimate, "not authoritative billing data"; no engine principal, measured-execution authority, repository adoption, publication, independent review or Release permission is granted.

## 4. Identity, recovery and repository binding

| Binding | Gap and required handling |
| --- | --- |
| Original task ID/digest | The pinned interface establishes no native exactly-once dispatch guarantee. The documented `sessionId` option ("Use a specific UUID for the session instead of auto-generating one") selects an identifier but supplies no deduplication semantics; a native session ID is **not** a caller-controlled task idempotency key. Durable reservation serializes local duplicates; the crash window between native start and persisted identity observation remains. Conflicts and tombstones follow [contract section 4](../EXECUTION_CONTRACT.md#4-task-identity-and-durable-admission). |
| Native handle | Reserve a pending mapping and durably bind observed session identity. A host-selected UUID alone cannot prove start, identity or deduplication. Recovery with a bound identity additionally needs the separately retained original-stream completion, not a history helper returning a synthetic result. Lost completion, mirror errors or missing identity leave admission uncertain and block every second start. `EXECUTION_NOT_FOUND` is an observation error. Never retry, resubmit, replace the UUID, resume-as-retry, redirect or fall back. |
| Session continuity | `forkSession` is documented as "not a byte copy" (it rewrites session IDs and remaps message UUIDs) and is excluded from recovery. The `SessionStore` is a mirror: the subprocess writes each transcript batch to local disk first, store entries are opaque and order-preserving, and a resumed run's store holds the only durable copy. Durable atomic reservation, sequences, capacity and restart handling remain adapter/host obligations, not guarantees of the in-memory fixture. |
| Immutable revision | `cwd` and native Git tooling enforce no immutable binding. The host must prove repository membership and preserve the approved checkout/isolation binding throughout work; a one-time HEAD check does not exclude concurrent checkout changes. |
| Project/repository/Strata model | Trusted-host/journal bindings, never native request-selected authority. `Options.model` is operator LLM configuration, not `binding.model_version`. |

The accepted offline admission core at `7285ffb` was reviewed as context only. It separates host admission/status/output retention from adapter native mapping: a host observation marker is not a native handle; successful status does not authorize result retrieval; an unobserved reservation stays uncertain; missing/corrupt state refuses; output expiry retains permanent task identity. Compose future adapters through those existing ports in a separately authorized implementation. This four-file proposal changes no admission or storage code and establishes no production durability.

## 5. Limits and cancellation gaps

| Bound | Evidence and qualification requirement |
| --- | --- |
| Control call at most 10 seconds | A wait timer bounds caller waiting only. After invocation, timeout/abort is dispatch `unknown`; native work may continue. |
| Requested runtime at most one hour | No hard wall-clock task deadline is established for this selection. `API_TIMEOUT_MS` (default 600000 ms) bounds a single API request and `CLAUDE_STREAM_IDLE_TIMEOUT_MS` clamps stream idle at 300000 ms; neither bounds a task. A bridge timer plus cooperative interrupt is a proposed expiry response, **not proof of enforcement**; only an observed interruption attributable to the timer supports `TASK_DEADLINE`. Failed/unresponsive interrupt and completion races require evidence. No process-kill fallback is selected. |
| Agentic turns and budget | `maxTurns` ("Maximum agentic turns") and `maxBudgetUsd` (client-side cost estimate; crossing yields the documented `error_max_budget_usd` result) are documented stoppers that can support observed `TASK_LIMIT` outcomes. `taskBudget` is API-side and marked Alpha; it is not relied on. |
| Result at most original budget/64 KiB; at most 16 artifacts | DTO checks cover normalized results. A future adapter must cap raw stream bytes before parsing and enforce native work/output/storage limits. No native output-size guarantee is documented; unsupported bounds block qualification. |
| Task/status at most 32 KiB; instruction at most 16,384 JS string units | Reuse [schemas](../../../src/agent-execution.ts) and the [guarded client](../../../src/agent-execution-client.ts); apply raw transport bounds independently. |
| Non-interactive execution | The `permissionMode` choice plus fail-closed `canUseTool` are reviewed literals, not proof that every prompt, elicitation or user-dialog path is disabled (`onElicitation`/`onUserDialog` exist in `Options`). Qualify the effective policy and tool set; never synthesize approval, widen grants or claim tasks cannot block. `bypassPermissions` is forbidden. |

The bridge owns monotonic sequences and content/result/artifact digests; native shapes supply no execution/1 equivalent. Terminal snapshots stay immutable. `cancel_requested` confirms neither stopping nor cleanup of side effects, and a plain interrupt receipt is not proof this task stopped. `cancelled` requires runtime evidence for this exact task.

## 6. Errors

The [shared rule](../EXECUTION_CONTRACT.md#6-errors-and-recovery) applies at **adapter method invocation**, not native SDK call. Every failure after invocation is conservatively dispatch `unknown`, including spawn/stream failures, validation and journal conflict. Only a refusal before adapter invocation may be `not_dispatched`.

| Condition | Proposed outcome |
| --- | --- |
| Spawn, stream or bridge transport failure, bridge crash | `EXECUTION_UNAVAILABLE`, `EXECUTION_TIMEOUT` or `EXECUTION_ABORTED`; dispatch `unknown`; retain uncertainty, explicitly inspect the original ref; no retries |
| Journal conflict / changed digest on a retained key | `EXECUTION_CONFLICT`, dispatch `unknown`; retain the original identity, reconcile the changed payload |
| Identity lookup unresolvable (no retained native identity, unknown store entry) | `EXECUTION_NOT_FOUND`, dispatch `unknown`; an observation error, not proof that execution never occurred |
| Observed result subtype `error_max_turns` | `failed` / `TASK_LIMIT` (observed native stop) |
| Observed result subtype `error_max_budget_usd` | `failed` / `TASK_LIMIT` (client-side estimate crossing; usage excludes the crossing response) |
| Observed result subtype `error_during_execution` | `failed` / `TASK_FAILED`; cost fields may be zeroed on crash results |
| Permission or sandbox refusal outcomes | Candidate `failed` / `TASK_POLICY`; the exact native representation is unverified and must be qualified before use |
| Retrieval budget refusal | `EXECUTION_LIMIT`, dispatch `unknown`; no success result. `TASK_LIMIT` requires a qualified adapter/runtime outcome, not merely a failed read. |
| Result requested without a succeeded snapshot for that request | `EXECUTION_RESULT_UNAVAILABLE` |

The pinned mirror declares `SDKResultSuccess.result: string`. `error_max_structured_output_retries` is a documented error subtype; proposed mapping is `failed` / `TASK_FAILED` only after qualifying its attributable terminal semantics. Error fields such as `errors` are not persisted. Installed-interface/native conformance is still required. Unknown native error variants must fail safely without copying their content. Native messages, environment, stacks and credentials never enter persisted error records, and an observation failure is never invented into a terminal task state.

The validator checks shared DTO schemas, identities/digests, transitions, conservative dispatch certainty, reviewed interface literals and the claimed source pins, and rejects deliberate result/ref/sequence/artifact/pin substitution in memory. It neither executes a mapper nor validates complete native messages against the interface text.

Before implementation/qualification:

1. Verify installed package/interface and binary provenance against the registry pins and mirror fingerprint; exercise full native messages, the one-input generator lifecycle, receipt capability detection and bounded parsing. A complete mirror read and metadata pairing are insufficient.
2. Establish original-ID recovery when the reply is lost before identity observation, concurrent duplicates and restart. Establish whether abort terminates or abandons the native process. If native identity cannot be proved, report unsupported recovery and leave the candidate unqualified; no new architecture or exactly-once claim is supplied here.
3. Establish interrupt-after-terminal and repeated-interrupt behavior, exact-task stopping, cancellation/deadline/completion races, unresponsive runtimes and enforceable runtime/output/storage bounds. Cooperative timers alone do not satisfy this gate.
4. Establish separately retained original-stream completion attribution (history is insufficient), best-effort mirror loss handling, deterministic frozen results, raw caps, immutable repository isolation, effective non-interactive permission policy and current grant checks before and after each operation.
5. Implement and review in a separately authorized slice, preserving Cloudflare-first sequencing and KIT/CF/Settings ownership. Accepting this proposal causes no compatibility upgrade, activation or row promotion.
