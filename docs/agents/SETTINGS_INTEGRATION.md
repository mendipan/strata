# Agent Settings integration

The [persistent connection extension](PERSISTENT_CONNECTIONS.md) saves exact owner consent and enabled intent across restarts, adds Retry/Revoke controls and separates consent, service-session expiry and runtime health. Real service authentication/renewal and tasks/tools/chat remain unconfigured.

This slice exposes the [synthetic lifecycle](CONNECTION_LIFECYCLE.md) through installation-owner routes, a one-shot CLI client and the existing Settings page. It does not provision a real service, authentication, state, source authority or credential slot. The unchanged hosted launcher omits the manager and returns authenticated unconfigured metadata with every agent action disabled. No agent inference, task, tool, instance creation or chat bridge exists.

## Actual routes and CLI

| Operation | Contract |
| --- | --- |
| GET `/studio/v1/owner/agents` | Bare `strata-studio-owner-agents/1`; current sealed owner required; local metadata only |
| POST `/studio/v1/owner/agents` | Existing owner cookie plus exact Origin, JSON and current CSRF; strict lifecycle action, CAS revision and original UUID; at most 1 KiB |
| GET `/studio/v1/owner/agents/operations/{UUID}` | Current owner; bounded retained pending/interrupted/completed/failed receipt; no dispatch |
| `strata studio agents status` | Same authenticated status route |
| `strata studio agents configure\|test\|connect\|retry\|disconnect\|revoke\|remove --file F` | Strict nonsecret JSON action file, at most 1 KiB; no generated revision or replacement request ID |
| `strata studio agents outcome --request-id UUID` | Same retained outcome route |

CLI commands require `--origin` with the exact approved HTTPS origin and `--username`, or an attended name prompt. Password entry is attended and not echoed, or explicitly supplied through protected `--password-stdin`. Passwords are not accepted as arguments, environment variables, URLs or stored sessions. Cookies/CSRF stay in process memory. Redirects and automatic retries are refused. Both clients share `OwnerSessionClient`; existing connection-client routes and behavior remain compatible.

The CLI closes its owner session before printing success. Its action status is an observation obtained during that session; `client_session={state:'closed',readiness_retained:false}` states that this CLI retains no session or readiness. Sign-out invalidates a new probe's ephemeral readiness; a metadata-only call or exact replay leaves another owner session's readiness unchanged. The durable connect receipt remains inspectable. A one-shot CLI connect is verification, not a background connection retained for another session. Failed/uncertain requests require the original UUID's outcome inspection before an explicit exact replay.

Bodies accept only `action`, `revision`, `request_id`, and `target_profile_id` for configure. GET rejects body/query; owner routes reject Authorization headers. Replies are bounded to 64 KiB and inherit the host's no-store, Origin/Host/proxy, CSP and sanitized-error protections. Reader keys and named-actor engine grants cannot authorize this owner API. Client/socket cancellation only stops bounded local waiting; it does not assert remote rollback. A lost response may follow actual completion, and the saved receipt remains authoritative.

## Trusted integration seam and default denial

`OwnerAgentSettings(manager?, profileIds?)` is a trusted server adapter accepted as `OwnerAccess`'s optional `agents` option. `profileIds` is a unique finite list (at most 16) of existing bounded profile identifiers for the selector. These are hints, not approvals; configure must be on this list and `AgentConnections` independently rechecks the current exact owner/source/target approval. No browser endpoint, auth header, module, registry provider or credential is accepted. The adapter never creates a store, grant or target and never loads probe credentials for status/outcome.

Projection adds `profiles`, `owner_confirmation_required`, and `reconciliation_scope={owner,state,authentication_generation}`. The owner hash binds installation and owner, remaining stable through password rotation; the state hash binds the immutable agent scope. Authentication generation is separate verified metadata. These nonsecret fields only namespace unresolved browser actions; they confer no authority. Unconfigured status has null revision/state scope, no profiles/connection, disabled actions and unconfigured engine authority. A malformed/missing manager store fails closed through the existing lifecycle; there is no fallback genesis creation or lease reclaim.

Owner authority is resolved from the current sealed `OwnerAccess` session on every call. Freshness is returned as verified metadata so the lifecycle can return `OWNER_REAUTH_REQUIRED` for configure/remove. Probe-attempt sessions are tracked only in memory: their logout, expiry or reauthentication synchronously invalidate the optional manager. A metadata-only session or exact replay does not adopt another session's readiness and its close does not invalidate it. A failed explicit probe attempt may conservatively invalidate runtime on sign-out. Password rotation/recovery and host clear invalidate all runtime. A future source/target/auth adapter must call `changed()` synchronously when its local generations change, and the lifecycle continues to recheck those ports before dispatch/finalization/cached readiness. Saving the unrelated Artifacts token supplies no agent authentication.

The trusted Settings bridge captures the lifecycle's synchronous `projectionGuard()` before status and checks it after its final asynchronous owner projection. A changed local epoch/runtime identity or elapsed discovery expiry clears current discovery/readiness and disables configure/test/connect. Historical evidence remains. Owner identity and authentication generation are independently compared across that final await; a change refuses the response. The guard creates no approval or authority and does not perform another asynchronous snapshot.

## Settings behavior and evidence

Settings retains its existing cards, fields, toolbar, credential section and responsive styles. Agent controls are local configure, explicit test/connect/disconnect/remove, status refresh, password confirmation, and outcome inspection. Status never probes. Current verified discovery and its expiry are separate from historical tests and finite advertised service features. Engine authority is separately unconfigured and authoring/execution/chat remain false. Non-owner preview/shared-reader/actor surfaces show an unavailable explanation and dispatch no owner-agent request.

Before dispatch, the browser retains only the strict nonsecret action and its original authentication generation in bounded `strata-studio-pending-agent/2` session storage under the stable owner/state namespace. Response loss, cancel, navigation and reload keep the original UUID. The same owner can explicitly inspect an unresolved outcome after password rotation; another owner or state cannot adopt it. Exact replay remains restricted to the original authentication generation by both UI and server. No action is automatically inspected, retried or reconnected. After an explicit NOT_FOUND, a metadata refresh must succeed before same-generation exact retry is offered; an old-generation absent action can only be dismissed. Pending/interrupted outcomes never cause another probe. Removal requires confirmation; Escape restores focus. No secrets, URLs or service-supplied markup are stored/rendered as authority.

A refused or failed status refresh marks the panel **Status unverified**, hides current discovery and service-feature claims, and disables lifecycle actions. Retained test evidence is explicitly historical. A successful metadata-only refresh restores confirmed status and eligibility without loading authentication or probing the service.

`studio-agent-settings.test.ts` exercises real owner sessions/files, HTTP boundaries, CAS, freshness, current outcome/replay, final-projection revocation/expiry, stable recovery identity with original-generation replay refusal, actual socket loss, logout during an exchange and actual CLI subprocesses with replaced transport/protected synthetic stdin. `studio-agent-settings-browser.mjs` exercises real Edge with intercepted loopback HTTPS, keyboard configuration, removal cancellation/focus, 320px/200% layout, current versus historical discovery, response loss/reload, exact retry, late completion after cancel, and unconfigured denial. `studio-agent-settings-recovery-browser.mjs` adds refused/transport refresh, successful metadata recovery, same-owner rotation for completed and absent receipts, and cross-owner isolation. All fixture targets and passwords are synthetic. Existing lifecycle restart/crash/rate/identity tests remain applicable; browser evidence does not establish a real service or screen-reader speech output.

## Decisions still required for a usable real connection

1. Identify the intended existing deployed service, fixed discovery path, service/instance IDs and exact project/model/immutable repository binding. The existing non-inference discovery contract must be implemented there; the SDK version alone does not supply it.
2. Select the service's actual authentication scheme and independent identity verifier. Approve the bounded network target and expiration. Implement only its required credential slots with proper domain separation and migration tests; neither the Artifacts token nor owner password is an agent credential.
3. Review host provisioning for the private immutable agent scope/genesis/state, path disjointness, target approvals, authentication generations and a selected-source adapter that preserves managed/legacy source grant and ledger lineage. Startup must not initialize/reset state. This slice intentionally adds no host configuration or operator setup command for those unresolved decisions.
4. Qualify the exact adapter and injected ports with synthetic protocol/auth/revocation and Linux persistence tests, then separately authorize exact real-service conformance. No real compatibility claim precedes that evidence. Engine principal/grants, authoring, task execution and chat remain separate future authority/bridge work.

Hosting T1 is an external source transition using the existing `source_management` factory. This slice changes neither that factory nor the launcher, source reader, read budget, legacy triplet, managed catalog, ledger or root custody record. Any later code-only deployment before T1 activation needs its operator's separately verified runtime packet rebind; it cannot migrate, renew or reset a grant.
