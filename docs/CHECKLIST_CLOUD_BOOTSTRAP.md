# Attended checklist bootstrap

The separately approved [app-only model diagnostic](CHECKLIST_MODEL_DIAGNOSTIC.md) collects bounded public model evidence without continuing to the second Worker or full demo. It requires an explicit purpose in CLI/activation/plan, runs at most 13 work plus two unchanged cleanup exchanges without retries, and always reports billing unresolved. See that document for fresh-target preparation requirements; this code change authorizes no live attempt.

The separate `--worker-version-diagnostic` purpose collects the second Worker's exact-version comparison and always stops there. The package, owner permission, plan and CLI must all select that purpose. It requires `retain` for Workers and repository, allows at most 17 exchanges, performs no retries or DELETE calls, and produces no runtime grant. There is no Workflow definition PUT, instance creation, archive write, token creation or app invocation. Both private Workers remain available for later explicitly authorized inspection, including on failure. A completed diagnostic reports the configuration comparison as `match` or `refused` independently of evidence collection; neither result means the application ran. The full budget hold and unresolved-target quarantine remain. This mode cannot reuse full-run authority or continue into the full run.

The named `/workers/scripts/{name}/settings` readback uses Cloudflare's [Script and Version Settings contract](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/script_and_version_settings/methods/get/). Bindings (order-independent with unique names), compatibility date/flags, limits, disabled Logpush and Standard usage retain exact comparisons. Observability reuses `checklistWorkerObservability`: top-level `enabled` and nested `traces.enabled` must explicitly match the reviewed true flags, while provider-added sampling/log/trace defaults do not have to equal the partial request object. The exact Worker version, module bytes, deployment at 100% and disabled public endpoints remain independently checked before this readback.

A settings refusal adds `settings-validator-refused` to the external reservation journal, bound to the response sequence. Its fixed diagnostic lists known field paths with actual types and `match`, `missing`, `invalid-shape` or `different` classifications. Diagnostic version 2 additionally retains only the exact public `usage_model` enum (`standard`, `bundled` or `unbound`); other values and shapes are `[redacted]`. It records the required `standard` separately and retains no arbitrary result values, dynamic binding names, unknown keys or exception text. See [independent settings fixtures](../tests/fixtures/checklist-worker-wire/README.md). This is an offline contract correction, not a proven explanation of a historical refusal whose result values were not retained. No existing consumed activation, journal, quarantine, budget hold or unqualified cleanup absence is reset by this change; successor source review and fresh exact authorization remain required for any later attended execution.

The [beta version-create contract](https://developers.cloudflare.com/api/resources/workers/subresources/beta/subresources/workers/subresources/versions/methods/create/) documents the deprecated optional `usage_model` field at the top level of the JSON body. The [pricing contract](https://developers.cloudflare.com/workers/platform/pricing/#how-to-switch-usage-models) retains legacy cases, so billing remains unresolved. Account default alone cannot replace exact-version evidence. All other mismatches still stop before Workflow/grant/instance creation. No automatic PATCH, model switch, mutation retry or billing-plan change is implemented. Existing holds and historical evidence remain unchanged.

This is a bounded deployment/operator addition to the hybrid checklist bridge. Node retains authoring, reviews, measured semantics and Release. The cloud components archive that exact published history and execute fresh instances of its exact generated collection module. No hosted semantic loop, current contributor authority or persistent application state is introduced.

The preparer produces disabled configs and a complete source/tool graph outside every Git checkout. Bootstrap code is included in that graph. `checklistBootstrapPlan` supplies a reproducible plan digest; `strata-checklist-cloud-activation/1` requires exact preparation/source/target/config/plan hashes, an attended external evidence directory, owner approval with a maximum two-hour start window, existing Standard Paid and required-permission attestations, a $1 gross attempt bound, a common absolute `shared_budget_file`, `combined_gross_spending_limit_usd:20` and explicit cleanup/30-day local retention. The shared file must be the same owner-bound ledger for every participating paid Strata test lane. An unapproved packet refuses before credential custody or provider dispatch. Application reservations cannot establish an invoice cap.

After exact owner consent, authenticated preflight reads only the account's Workers settings, the intended existing Artifacts namespace and exact proposed names. It does not enumerate credentials, tokens, accounts or namespaces. Standard account settings and an existing accessible Artifacts namespace supplement the owner's existing Paid/permission confirmation; read success does not independently prove all write permissions or billing status. An unsupported/denied result stops. There is no access repair, permission expansion, alternate credential search, token renewal/rotation, login, new API credential, namespace, Access policy, tunnel, public route, subscription or contributor grant.

Private creation uses `POST /accounts/{account}/workers/workers` with both subdomain flags false, before any generated code upload. Capture the acknowledged immutable Worker ID and verify its private settings through an exact GET. This path is declared by Cloudflare's [official version 5.2.0 SDK](https://github.com/cloudflare/cloudflare-typescript/blob/v5.2.0/src/resources/workers/beta/workers/workers.ts), the version bundled in pinned Wrangler. The bootstrap sends direct native HTTPS requests, not the SDK's retry/pagination helpers.

Upload the exact app and Workflow bundles using [Worker Version create](https://developers.cloudflare.com/api/resources/workers/subresources/beta/subresources/workers/subresources/versions/methods/create/), `POST /accounts/{account}/workers/workers/{acknowledged_worker_id}/versions?deploy=true`. This beta API accepts JSON `modules` with base64 content, CPU/subrequest limits, compatibility settings and bindings. Construct that content from the same manifest-verified buffer that is dispatched. Worker-level observability (including traces) is set at private creation and verified on exact-ID readback. Bindings preserve approved plaintext pins, version metadata, the existing Artifacts namespace, private app service and self Workflow binding. Read back the returned version through the same exact Worker ID with `?include=modules`, checking required version identity, creation time/number, empty routable URLs, exact base64 module bytes, main module, bindings and runtime configuration. A later disk restoration cannot bless different uploaded or returned bytes.

The typed version create response's `id` denotes the Worker version. `deploy=true` explicitly creates a deployment serving that version at 100%. The named deployment GET must return the documented `result.deployments` object containing one deployment with that exact `versions[0].version_id` at 100%; its deployment `id` is separate. The same typed deployment parser serves downstream runtime retention checks. It preserves the documented active list head regardless of creation timestamps and refuses bare arrays, duplicate deployment IDs and malformed traffic splits. Direct script PUT's `id` means script name and its current schema supplies no version ID. Pinned Wrangler's legacy `deployment_id` and synthesized compatibility data are not direct wire evidence and are no longer consumed. The native Workflow ID and definition version remain separately read and cannot substitute for Worker version metadata. A fresh one-version Workflow must have the approved class, eight steps, concurrency one and one-hour success/error retention. Unsupported, incomplete or additional-page responses stop. See [documented response fixtures](../tests/fixtures/checklist-worker-wire/README.md).

The run grant binds the hash of the exact disabled config templates; only the computed authorization value replaces the empty disabled Workflow variable. Its authorization digest omits provider-assigned version identities to avoid a deployment hash cycle. The full grant freezes both Worker script versions and the native Workflow ID/definition version after readback. T starts before mutations, after complete fresh preflight; run expiry is T+30 minutes and cleanup expiry T+32. The bootstrap activation ledger and the runner's separate grant ledger use exclusive creation and fsync. A failed read-only preflight consumes no mutation authorization or runtime grant. A separately retained same-scope authorization may permit another fresh attempt with new evidence and timestamps; it never resets old ledgers. Mutation uncertainty blocks another same-target mutation until exact reconciliation is retained.

The full path waits 60 seconds after both private Worker deployments pass their checks and before registering the Workflow. The exact delay is part of the approved plan and its start/end are journaled. This controls startup timing; it does not prove global deployment readiness or justify restarting a failed instance. Synthetic runs record the boundary without sleeping. All real request deadlines and identity checks still apply.

After a verified application result and one acknowledged instance DELETE, cleanup may spend at most three physical GET attempts on the exact instance across transient retries and visibility polls, within the existing call/time allowance. Visibility polls wait up to 30 seconds; transient retries retain the fixed backoff below. Exhausted reads leave cleanup unresolved without another wait or DELETE. A still-readable response must identify the same completed instance; any other state or malformed response stops. Absence requires HTTP 404, provider code 10400 and a valid failed envelope. The exact public message `workflows.api.error.instance.not_found` is accepted alongside an unambiguous English absence message. Denials, other codes and extra fields remain refused. No deletion is repeated. Archive/Worker retention is checked separately, and neither successful cleanup nor a local parser repair clears a budget hold or historical quarantine.

Whole-instance subrequests replace the old maximum-phase calculation. For 62 records, closure/index/cold-read require conservative maxima 71+7+67=145. Two observations make the planned known count 147; the three-observation allowance makes 148. Reserve an additional 64 platform/lifecycle/state exchanges (eight per native step): 212 total. At the supported 80-record boundary this is 248. Pin `limits.subrequests` to 256, persist the complete allowance before mutations and verify it in the final result. The additional 64 is headroom, not measured provider-internal usage; the platform's configured limit remains a hard stop. Cloudflare's [Workflow limits](https://developers.cloudflare.com/workflows/reference/limits/) document whole-instance accounting and a configurable Paid maximum of ten million. There is no automatic widening.

The wire contract follows the [current instance create API](https://developers.cloudflare.com/api/resources/workflows/subresources/instances/methods/create/): `instance_id` plus a JSON-encoded parameter string. This deliberately supersedes the older pinned CLI's structured parameter body for direct REST calls. The Workflow entrypoint decodes this bounded string once before reading its grant; object payloads from native bindings use the same strict payload schema. Nested strings, malformed JSON, extra fields and oversized inputs refuse. Decoding changes no grant, source, version, identity, time or replay check. Native regression tests pass the serialized string into the runtime without decoding it in the fixture host. Creation must return the exact instance, Workflow and definition-version identities. The [status API](https://developers.cloudflare.com/api/resources/workflows/subresources/instances/methods/get/) returns `versionId` and need not return `id`; normalization binds the response to the exact named request and pinned definition. Complete single-page envelope metadata is accepted only when counts agree and no cursor/additional page exists. Any unsupported encoding or response shape stops; no alternate encoding, second POST or regrant is attempted. These are documented wire contracts and offline tests, not proof of live provider parity.

Bootstrap permits at most 24 work exchanges and eight partial-setup cleanup exchanges. The no-retry path uses 23 work exchanges including two exact version reads. Preflight is six logical GETs, capped at nine physical exchanges; exhausting the remaining work allowance fails closed. The runner permits at most 33 exchanges including cleanup. They are mutually exclusive cleanup paths: setup failure performs no run; a handoff delegates run/token/resource cleanup to the existing runner. Thus the maximum combined successful path is 57, below the 64-host-request approval ceiling. Every physical exchange is independently reserved before headers or HTTP. Version upload JSON and its upload/readback responses have a reviewed 2 MiB bound because base64 expands the real 0.8/1.3 MiB bundles beyond 256 KiB. Other JSON and responses retain 256 KiB bounds, and aggregate transfer retains its 64 MiB cap. Package qualification reserves base64 size, metadata allowance, four version responses and remaining management traffic, refusing oversize packages before dispatch. Plan/source/config pins therefore require successor review and a new exact activation. Safe GET orchestration admits at most three attempts with fixed 250/1000 ms backoff for tagged 408/429/500/502/503/504 or settled ETIMEDOUT/ECONNRESET/EAI_AGAIN failures. All attempts count against the original time, request and byte bounds. Each reservation still performs exactly one wire request with zero transport retries. Malformed bodies, denials, uncertain absence, redirects and pagination refuse. POST/PUT/PATCH/DELETE and Workflow steps never retry automatically.

The [shared gross budget](../scripts/checklist-cloud-budget.ts) uses exclusive file locking and atomic replacement across cooperating local processes. Initialization requires an explicit conservative prior gross-cost baseline, including fees/taxes, and its retained receipt hash; a missing or unknown baseline does not become zero. Read-only preflight holds one cent. Complete preflight promotes that same lease to 100 cents, including a 42-cent modeled net allowance and 58 cents of fee/tax headroom, before mutation. Unknown actual usage retains the entire hold; estimates never release money. This successor supplies no invoice reconciliation or quarantine-clearing operation. Stale locks and unresolved leases require operator reconciliation. Other machines and nonparticipating runners must be coordinated through this common ledger; the module alone does not bound their invoices.

The [diagnostic sanitizer](../src/checklist-cloud-diagnostics.ts) retains fixed classifications, bounded numeric error codes, known field types/counts and fixed validator stages. It never retains arbitrary server text, unknown field names, URLs, headers, result values or exception text/stacks. Named repository absence requires HTTP 404, NOT_FOUND code 10200 and the original not-found/no-authorization message predicates. Named Workflow absence requires HTTP 404/code 10200; named Worker deployments absence requires HTTP 404/code 10007. Those latter codes, recognized by pinned Wrangler and Cloudflare's [Workflow helper](https://github.com/cloudflare/workers-sdk/blob/main/packages/deploy-helpers/src/deploy/helpers/check-workflow-conflicts.ts) and [Worker helper](https://github.com/cloudflare/workers-sdk/blob/main/packages/deploy-helpers/src/deploy/helpers/worker-not-found-error.ts), carry the missing-resource meaning without an English phrase. Nonempty typed messages and the authorization-denial guard remain mandatory. Legacy-environment code 10090 refuses. Valid target, success:false, nonempty typed errors, empty typed messages, null/undefined result, no pagination and no unknown fields remain required. Instance absence is unchanged.

Repository errors admit only optional `documentation_url:string`; Workflow errors admit only code/message; Worker deployment errors admit their documented optional `documentation_url:string` and `source:{pointer?:string}`. Values are ignored, never fetched, followed or used as authority. Wrong types, unknown source keys or unknown error fields refuse. These are endpoint-specific schema/code contracts, not blanket 404 acceptance. See [Artifacts schema](https://developers.cloudflare.com/artifacts/api/rest-api/) and [Worker deployments schema](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/deployments/methods/list/). Remaining preflight contracts retain strict readiness/collision checks: Standard account setting, exact namespace and refusal of existing resources or empty deployment lists. Documentation's illustrative pagination/error examples are not live success/absence evidence.

The parser, successful bootstrap envelope guard and sanitizer share one conservative denial classifier. Access, privilege, allowance/permission, entitlement, prohibition/restriction, capability/role/scope/grant, insufficient/blocked/rejected terms and explicit action prohibitions refuse even with a missing-resource code. Sanitized output records the same coarse authorization classification without arbitrary text. This intentionally fails closed on ambiguous access-control terminology; it is not proof that arbitrary prose or the lost actual Workflow message has been semantically understood.

Partial setup honors the owner's Worker retention selection even after failure. `retain` makes no DELETE calls and records acknowledged identities and possible remnants; incomplete setup retains the full budget hold and same-target quarantine. `delete` removes only acknowledged session-owned resources using captured immutable Worker IDs and the exact newly acknowledged Workflow. Worker IDs admit exactly 32 hexadecimal characters and retain their spelling; Workflow/version UUID rules are unchanged. Lost creation acknowledgements remain possible remnants, never ownership inferred from a name. Private Worker DELETE accepts its documented acknowledgement, then reads the exact private entity ID. The observed strict 404/10007 negative contract is described in [the model/cleanup policy](CHECKLIST_CLOUD_MODEL_POLICY.md); script deployment absence cannot substitute for it. Historical recovery evidence and cost holds remain governed by the separate [recovery contract](CHECKLIST_WORKER_CLEANUP.md).

It identifies which comparisons failed without storing binding text, module code, arbitrary server values, unknown property names or exception text. Only numeric limits and allowlisted public default labels are retained. All version acceptance checks remain unchanged; a diagnostic cannot authorize normalization, retries or mutations. Failures after instance dispatch preserve the existing runner's token/handle uncertainty protections. Preserve first-attempt receipts and cold readback before deleting the temporary repository, instance, Workflow and both Workers. Keep the existing namespace and unrelated resources. The deployed-script runner remains a separate contract and does not qualify private-entity absence.
