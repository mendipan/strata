# Local Profiles/Build adapters

Local means the machine running Studio. This adapter emits and verifies the finite `collection-host/1` module with JavaScript, no framework, and Node >=22. Application run/serve remain false. Cloudflare Worker is reported unsupported. It does not contact providers or configure credentials, grants, installed tools, or output directories.

`openLocalBuildRepository` takes a host-owned `AuthorityIssuer`, admitted `ProfileServiceScope`, existing Node registry directory, `LocalBuildOutput`, and host environment resolver. It obtains the existing descriptor lease and uses the existing canonical registry, immutable artifacts, request receipts, commit audit, and atomic index replacement. Do not open it concurrently with `startLocalBroker` or `openProfileRepository` on that directory. Its transaction queue covers short registry work; the S2 coordinator calls its child transactions outside that queue. The bounded finite measurement transaction does not recursively call a broker.

The adapter composes S1 `BuildProfileService` and S2 `LocalBuildCoordinator`. It does not replace generation, checkers, publication, or review authority. Contract import/adoption requires an exact retained S1 review; the private `review` method uses the same repository-operation and pinned Release-review authority. There is no public review endpoint, automatic approval, or owner-derived grant. Saved profile revisions and post-publication adoption pins are never replaced by names or the current authoring head.

Build operations require explicit policy/4 operation membership and `build_repository_ids`. Older policies acquire nothing. Prepare/start also check the current finite materialize/register/runner/inspection/output entitlements. Each child execution and final registry rename checks live authority again. `LocalBuildStudioAdapter` supplies the existing actor resolver to `StudioCommands`; an unconfigured host, including a namespace backend without explicit mounting, reports these operations unsupported and gets no output slots or grants from this change.

The CLI uses `repo compatibility`, `repo contract import/attach`, `profiles list/show/validate/create/revise/archive`, `build context`, `build plan`, `build`, `build status`, and `build outputs`. Build uses `--profile-ref`; historical `materialize --profile` keeps its meaning. `--idempotency-key` identifies the original mutation. Timeouts require inspection of that original request/attempt. A retry that performs new effects needs a new key and allocation.

Studio read/preview routes are `/studio/v1/profiles`, `/profiles/record`, `/profiles/validate`, `/repository/compatibility`, `/build/context`, `/build/status`, `/build/outputs`, and `/build/preview`. Mutations use the existing `/studio/v1/operation`. `/studio/v1/build/output` accepts only `build_id` and `file_id`; current access and exact bytes are checked before returning an attachment. Existing host session and origin gates still apply. `localBuildHttpHandler` is a mountable local command-envelope adapter; it creates no listener or authentication system and requires the host's origin/CSRF gate before accepting browser requests.

Two supporting record types retain immutable history: `build-attempt-revision` (full-run CAS, predecessor and exact authenticated writer input) and `build-child-receipt` (original project/repository/build/actor/action/key/input/result/authentication). Their shared admission check verifies exact profile/adoption/publication closure, realization pins, finite checker/fixture/oracle/producer pins, and mechanical coverage. Read/backup admission recognizes them. Backup/4 preserves these bytes and historical materializer archives; restore remains inactive, with no request-cache or login/grant activation. Output files are separate host I/O and are not restored by semantic backup.

Startup `reconcile` is private and requires explicitly assigned `build.reconcile` plus current inspection rights under exclusive installation ownership, before accepting requests. It only reads an original registration receipt. Lookup cannot ask for another project, repository, actor, build, action, or key. An absent receipt is **unknown**, never proof of no effect. A committed receipt retains exact output pins and closes the attempt as interrupted; it does not replay registration, export, or checks. No terminal success is invented. `operation.inspect` remains an original-actor request lookup; interrupted builds can also be read through `build.inspect` under current repository access.

Qualification limits: the tests use admitted synthetic publication history, named synthetic host accounts, and mocked output custody. Real Windows/Debian service identities, ACL/ownership, the complete source/registry/credential/document-root exclusion inventory, and private registry/config custody require attended host qualification. The adapter requires its registry in the output exclusion inventory, but cannot discover every protected installation location. Process-death testing proves that an abandoned descriptor lease refuses reopening; controlled response-loss/reopen testing proves receipt reconciliation. It does not prove unattended recovery after a kill at every export/check/fsync boundary or power loss. Windows directory-fsync durability is not claimed. Stale descriptor leases and allocation claims require a separately controlled procedure with proof the host is stopped. No timeout stealing, lease remover, or live recovery monitor is supplied.

Namespace profile persistence is mounted separately on the existing authoritative writer; see [the namespace Profiles interface](studio/NAMESPACE_PROFILES.md). Local output/runner integration and attended installed-host activation/rehearsal remain separate work. This Local slice remains independent of the hybrid demonstration and the older blocked engine-reconciliation S3 work.
