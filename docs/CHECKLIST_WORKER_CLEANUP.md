# Private Worker identity recovery and cleanup

This is an offline review contract for an undeployed private Worker whose original creation acknowledgement was retained as a canonical response hash. It supplies no transport, credential access, live authority, ledger transition or executable cleanup CLI. A frozen plan has `execution_enabled:false`. A parent operator must separately review and implement any later execution under cleanup-only authority.

The [Worker create API](https://developers.cloudflare.com/api/resources/workers/subresources/beta/subresources/workers/methods/create/) documents an immutable string ID. The local admission policy accepts exactly 32 hexadecimal characters, based on observed evidence. It rejects hyphenated UUIDs, arbitrary strings, malformed lengths and path/query injection. It preserves case and never normalizes the value. Workflow, definition and uploaded version UUID checks are unchanged.

The [GET API](https://developers.cloudflare.com/api/resources/workers/subresources/beta/subresources/workers/methods/get/) accepts ID or name. Recovery requires a separately reviewed hash of a strict proof: exact account/name/ID/timestamps, original consumed activation, bridge candidate/source/target pins, reconciliation-plan hash, and both exact-name and exact-ID HTTP 200 receipts. Both receipts must match the original POST response hash and identity. A name-only lookup cannot recover ownership. Operational proof values belong in external evidence, never in repository fixtures.

Before DELETE, a fresh exact-ID HTTP 200 read must match the entire original canonical response hash, exact name/ID and unchanged timestamps. It must explicitly return `deployed_on:null`, disabled subdomain/previews, logpush false, five empty reference arrays, empty tags/tail consumers and no preview base configuration. A missing `deployed_on` does not prove never deployed. Subdomain URL/preview suffix fields may be present when flags are disabled; their presence alone is not evidence of exposure. Fractional timestamp strings retain their full precision.

Fresh cleanup authority must bind the reviewed successor commit, recovery proof, cleanup plan, consumed original activation and exact identity. It permits one DELETE, no force, and requires quarantine and cost hold preservation. Authority expires within 15 minutes; the pre-delete read must follow approval and be at most 60 seconds old. The consumed original activation is not reused. All requests specify one exchange, no retries, manual redirects and refusal of pagination. The exact-ID DELETE has no query/body or name fallback.

The pure reducer returns a `delete-reserved-uncertain` state before dispatch. A future executor must atomically create an exclusive durable journal for this recovery and consumed activation, fsync the reservation before HTTP, and refuse a second reservation across processes or restarts. The reducer does not enforce durability by itself. Reinitializing its state is not authorization to retry. Failed journal writes, transport loss, malformed acknowledgements, denials, redirects, timeouts or crashes retain uncertainty. No DELETE replay, renewal, fallback or cleanup loop is permitted.

The [Worker DELETE API](https://developers.cloudflare.com/api/resources/workers/subresources/beta/subresources/workers/methods/delete/) documents HTTP 200 with success/errors/messages and may omit result. The parser admits omitted or null result, empty errors and only typed non-denial diagnostic messages with documented optional fields. It refuses arbitrary result objects, unexpected fields, pagination and any other HTTP status. It retains the complete response hash and fixed sanitized diagnostic, without arbitrary messages/headers. An acknowledgement is not absence evidence.

Follow-up reads address both exact private-entity ID and exact name on `workers/workers`. They may run after acknowledgement or an uncertain DELETE, while the one-delete reservation stays consumed. Their response hashes and safe diagnostics can be retained for review. The actual private-entity 404 has not been observed, and current GET documentation supplies no unique absence code. Every observation therefore remains `verified_absent:false`; no synthetic negative is represented as actual evidence. A same-name replacement, denial, ambiguous response or script-deployment 404 cannot clear quarantine. A later endpoint-specific negative contract needs independent review before private absence can be verified.

The historical recovery reducer above still preserves uncertainty and cannot release quarantine. Bootstrap partial cleanup now has a separate [observed exact-ID absence parser](CHECKLIST_CLOUD_MODEL_POLICY.md), using its own captured Worker ID after acknowledged DELETE. This does not rewrite historical recovery records. Deployed-script management endpoints remain separate. The budget module has no reconciliation/clear-quarantine operation: verified absence cannot release the full mutation hold, estimate actual spend, reset a lease, or reuse an activation.

The focused tests cover malformed/UUID/path-injected Worker IDs, case-sensitive equality, same-name wrong-ID, ownership proof mismatch, changed deployment/private/reference state, stale reads, authority pins, typed DELETE acknowledgement, denials/pagination, duplicate cleanup and uncertainty. They use synthetic seams and do not establish provider interoperability, deployment, archive success or a measured invoice.

The adjacent bootstrap response review confirms that [Workflow metadata](https://developers.cloudflare.com/api/resources/workflows/methods/get/) and [definition versions](https://developers.cloudflare.com/api/resources/workflows/subresources/versions/methods/list/) still document UUIDs. Their existing guards remain. The [script upload schema](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/update/) does not document the legacy `deployment_id` field required by the current bootstrap, although the pinned Wrangler source consumes it. This unresolved compatibility assumption must be reviewed before another full bootstrap attempt. This correction neither changes version ownership semantics nor qualifies a deployment path; exact private cleanup does not use uploads or Workflow responses.
